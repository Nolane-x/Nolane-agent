# Forge Studio 2.24.0 verification contract

The release is accepted only when the required Full Release Matrix passes on a clean commit. The `long-horizon-construction` gate verifies:

- contradictory hard constraints block editing before provider execution;
- acceptance criteria are complete only through a live trace to passing, current verification evidence;
- critical or stale invariants block patch authorization;
- hierarchical plan steps enforce preconditions, expected state and verification receipts;
- repository or assumption drift invalidates unfinished plan steps;
- state capsules resume only when repository, plan, invariant and Git checkpoint identities still match;
- prospective obligations cannot complete before their trigger and required verification;
- hard constraints dominate negotiable goal trade-offs;
- public API breaks, generated edits, permission expansion and budget excess are rejected before mutation;
- candidate correctness precedes semantic footprint and resource efficiency;
- completion claims require criteria, traceability, invariant, verification and rollback receipts;
- lazy integration and application composition budgets remain intact;
- the 1,150-item audit and all non-claims remain honest.

The measurement is deterministic Core behavior evidence. It is not an independent agent-quality benchmark, a production certification of every OS reboot path, or evidence of comparative superiority.
