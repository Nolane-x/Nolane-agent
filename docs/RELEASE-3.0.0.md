# Forge Studio 3.0.0 — Frontier Governance

Forge Studio 3.0.0 introduces a bounded governance layer for cross-repository change, post-merge self-healing proposals, long-term change-survival feedback, cultural lineage, and constitutional self-improvement evaluation.

## Release scope

- Cross-repository repository/contract/dependency graph with version and provenance receipts.
- Transactional change plans with dependency order, compatibility windows, verification checkpoints, and all-or-rollback coverage.
- Synchronized prepared-commit chain with per-repository verification and mandatory human merge approval.
- Post-merge CI/crash/log/performance/security signal ingestion and direct incident attribution.
- Clean-baseline self-healing worktree proposals with regression tests, bounded leases, rollback, and no merge or publish capability.
- Seven-to-thirty-day survival observations and shadow-only router/skill credit.
- Versioned cultural lineage for skills, policies, architecture decisions, and memory.
- Immutable self-improvement constitution with held-out, regression, red-team, shadow, canary, rollback, viability, and human gates.
- Mandatory `frontier-safety-and-self-healing` release gate.

## Audit

The 1,150-item audit records 959 source-and-test verified requirements, 115 partial requirements, 63 external gates, and 13 not implemented requirements. Source of truth: `docs/feature-audit-3.0.0.json`.

## Non-claims

This release does not autonomously merge or publish, execute production policy promotion, expand autonomy, certify real 7–30 day field survival, or claim superiority over competing agents. See `docs/LIMITATIONS-3.0.0.md`.
