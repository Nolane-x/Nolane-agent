## Current release/update truth discovered for Task 12

The release workflow intentionally has different platform semantics:

- **Windows:** signed NSIS update trust is enabled in the production release path and the in-app installer handoff is the supported native path.
- **macOS:** DMG + ZIP are built, but production update trust/native install handoff is intentionally disabled until a real native handoff is verified.
- **Linux:** AppImage + DEB are built, but production update trust/native install handoff is intentionally disabled until a real native handoff is verified.

The current renderer update notice cannot fully express this distinction because `desktop/update-coordinator.cjs` does not yet project platform/install-handoff truth into the public update state. The renderer also contains generic staged/install language and a hardcoded Expert fallback that can read like `staged NSIS` even when the product surface should be platform-aware.

This is the first architectural target of Task 12. Do not solve it with copy-only branching or inferred platform claims.
