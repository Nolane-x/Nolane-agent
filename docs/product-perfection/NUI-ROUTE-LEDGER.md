# NUI Route Justification Ledger — Nolane Product Perfection v3

**Purpose:** durable record of which Nolane UI Intelligence decision owners are materially relevant to each perfection slice, why they are activated, and which high-impact faculties remain omitted or deferred.

This is a routing ledger, not a claim that every named skill has empirically caused an improvement. The host/repository remains authoritative for permissions and execution.

## Task-profile checksum

- **Product:** local-first desktop AI-agent professional workspace.
- **Platforms:** Windows, macOS, Linux Electron desktop; source runtime used for browser-render evidence where appropriate.
- **Primary users/jobs:** goal-to-mission execution, project/session continuity, supervised autonomous work, intervention, evidence/review/recovery, provider/model/tool control.
- **Visual ambition:** flagship / exceptional micro-detail maturity.
- **Approved regimes:** Everyday, Workspace, Studio, Expert over one canonical product model.
- **Product-native thesis:** Proofborne Instrument.
- **Signature mechanism:** Evidence Spine / Trace.
- **High-risk dimensions:** permissions, autonomous action, provider/model truth, browser trust, destructive mutation, evidence freshness, update/recovery, accessibility, platform differences.
- **Required evidence capability:** source tests, GitHub runtime render, Axe/runtime assertions, performance traces, Windows/Linux/macOS runner receipts; independent/provider-real claims only when real evidence exists.
- **Reference boundary:** learn mechanisms from mature professional tools/Codex-class products; never copy recognizable trade dress.
- **Hard constraints:** generated UI distribution only through canonical builder; missing evidence = UNKNOWN/BLOCKED; causal diagnosis before symptom patches; no blanket “premium” decoration.

If a future task materially changes one of these fields, update this checksum before routing.

**Observed trigger:** the user requires hundreds of tiny details to remain owned across AI/context loss; ordinary prose polish is too easy to forget or self-certify.

**Activated NUI faculties / decision classes:**

**Why:** the main failure class is omission and unsupported completion, not visual taste alone.

**Explicit omissions:** media sourcing, 3D/XR, automotive/TV/wearables, financial/medical domain specialists — no current trigger in Nolane desktop product truth.

**Evidence:** `PFX-*` catalog + fail-closed matrix core. PASS requires evidence + exact revision.

## Slice PFX-02 — Projects upper-whitespace anomaly

**Observed trigger:** rendered Projects route showed a large blank band with no causal source explanation.

**Activated NUI faculties / decision classes:**

- rendered visual iteration;
- professional desktop workspace architecture;
- responsive/layout reasoning;
- repository archaeology;
- causal adequacy critique;
- view-state/persistence reasoning.

**Omitted initially:** aesthetic direction changes, typography redesign, project-card redesign. They could not safely answer the causal geometry question and were intentionally deferred.

**Finding:** shell grid defined too few explicit rows for topbar + update notice + workspace. Empty update root consumed the flexible row, pushing workspace into an implicit row.

**Evidence:** before/after GitHub runtime geometry + screenshots; see `PROJECTS-LAYOUT-ROOT-CAUSE.md`.

## Slice PFX-03 — Shared micro-detail / density / platform-residue authority

**Observed trigger:** 310 catalog items cannot be closed coherently if every route invents its own spacing, state, density, selection, caret, scrollbar and optical rules.

**Activated NUI faculties / decision classes:**

- design-system/token governance;
- typography/spacing/surface craft;
- professional desktop workspace density;
- interaction-state accounting;
- platform behavior;
- rich interaction engineering;
- accessibility/focus/reduced-motion authority;
- modern interface residue audit;
- flagship adequacy/generic-transfer resistance.

**Required architectural decision:** perfection layers may strengthen page/flagship styling but MUST remain below final accessibility and responsive authorities in the cascade.

**Omissions for this slice:** route-specific information architecture and copy rewrites. Shared authority is established first; route-specific changes happen in later slices.

**Falsification:** if the new layer requires raw colors, duplicates accessibility focus ownership, uses one density value for all four regimes, or must use `!important` to function, the architecture is wrong.

## Routing maintenance rule

Before each later material slice (shell, adoption, Mission/Review, Studio/Browser, capabilities/Settings/Control Plane, release/update), add an entry that records:

1. observed trigger/failure class;
2. activated NUI decision owners/classes;
3. omitted plausible high-impact owners and why;
4. evidence capability available in that slice;
5. falsification condition.

Do not expand routing simply because a skill exists.
