# Forge Studio 2.18.0 — adversarial weakness matrix

| Area | 2.17 exposure | 2.18 response | Remaining weakness | Next evidence-driven action |
|---|---|---|---|---|
| Model-specific harness | Providers shared nearly identical instructions, tool ordering, retry rendering and patch behavior | Immutable family profiles and deterministic composition at the real call boundary | Built-in profiles are engineering priors, not learned optima for every model/version | Build held-out provider suites from verified failure clusters and maintain version-specific candidates |
| Failure feedback loop | Outcome/receipt data existed but did not feed a controlled harness experiment | Bounded taxonomy, privacy-safe store, replay comparison, explicit promotion and rollback | No operated production cohort, canary rollout or automatic rollback threshold | Add local cohort assignment and replay/canary receipts without sending raw prompts or outputs |
| Privacy | General logs were guarded, but harness tuning had no dedicated minimal schema | Strict telemetry allowlist rejects prompt, output, environment and unknown fields | Fingerprints and metadata can still require retention/tenant policy | Add TTL, project/principal partitioning and export/delete governance |
| Evaluation | Provider routing had eval support but no profile-to-profile gate | Same-suite dual-profile replay, critical-regression rejection and weighted efficiency score | Synthetic/local suites may not represent real repository diversity | Curate consented, redacted, reproducible repository tasks and held-out suites |
| Composition root | New adaptive systems risked increasing `app.mjs` coupling | Single Adaptive Harness Lab facade keeps 160 imports/180 constructors | Core composition remains large overall | Continue bounded-context extraction without weakening existing lifecycle gates |
| Process cost | Logical leases exist but child processes are not fully attributed | Not falsely claimed in 2.18 | Per-mission child CPU/RSS/FD accounting remains absent | Build process-tree ledger and provider/browser pool evidence next |
| Browser completion | Browser actions have admission but not end-to-end visual receipts | Not falsely claimed in 2.18 | DOM/a11y/network/console/screenshot/video repair replay remains incomplete | Build Playwright journey receipts and deterministic repair/replay gate |
| Repository intelligence | Shared scheduler reduces fan-out | Unchanged in 2.18 | LSP/build/runtime/coverage updates still lack one content-hash journal | Extend incremental journal after process accounting |
| Hosted lifecycle | PR/CI/deploy remain external | No false local claim | Issue→PR→CI→repair remains incomplete | Add least-privilege provider adapters only on operated infrastructure |
